# 功能模块完善与实现建议

> 本文档基于当前代码库（`ai-interview-hub`，Vue 3 + Element Plus 前端 / FastAPI + SQLAlchemy 后端）的现状盘点，列出尚需完善或未实现的功能模块，并给出实现建议与优先级。
> 优先级约定：**P0** = 功能断裂/安全隐患（必须修）；**P1** = 功能补全（影响体验闭环）；**P2** = 平台化与工程化（稳定后推进）。
> 已完成的功能模块已移至 [update_log.md](./update_log.md)（含第 1、2、2.5、3.5 批与题库管理/历史对比等 B 类补全：账号安全、能力诊断与岗位匹配真实化、消息推送与会话落库、模拟面试题库与组卷引擎、面试状态机与自适应追问、题库管理界面、薄弱题重练等）。

## 一、总体结论

- **核心短板集中在**：① 企业/管理端统计指标仍有写死项（招聘数据分析、AI 服务监控）；② 模拟面试仅剩候选人匹配度排行榜、AI 通道可观测（见第四章）；③ 平台缺少**缓存、限流、异步任务、监控**等基础能力。
- **已完成的补强（2026-09-28~29）**：面试会话状态机与非法迁移拦截（409）、中止面试端点、REST/WS 双通道统一核心服务、next_action 自适应追问真实生效、整场计时服务端化与归零自动交卷、**单题服务端超时校验与报告时间维度分析**、报告/列表/成长中心假数据清理、**语音假字段清零 + 浏览器原生转写/朗读 + 设备检测真实化**；**题库管理界面（M08）**、**同岗位历史对比**与**薄弱题一键重练**（B 类第 6、7、8、9 项全部完成，详见 update_log 与第四章标注）。

## 四、模拟面试补强项（参照 `docs/report.html` 对比，P1~P2）

1. ~~**会话状态机与非法迁移拦截**~~ ✅ **已完成（2026-09-28）**：`app/core/state_machine.py` 集中声明迁移规则，非法迁移（重复开始、重复提交同题、终态后操作）一律 409；新增 `POST /interviews/{id}/abort` 中止端点。REST 与 WS 已统一复用 `app/services/interview_core.py`，消除双通道分叉（含 competency_name 写死 "Redis" 问题）。
2. ~~**逐题倒计时服务端超时处理**~~ ✅ **已完成（2026-09-28）**：新增 `Interview.current_question_shown_at` 呈现时间锚点，服务端按锚点计算真实单题用时并覆盖客户端上报；超时轻扣分（每 30 秒扣 3 分、上限 15 分、不归零）写入评分证据，空作答直接 0 分并提示；暂停时长通过 `paused_at` 从计时中剔除；报告新增 `time_analysis`（用时分布、超时率、超时集中技能）。
3. **候选人匹配度排行榜**：`/enterprise/candidates` 已算出 `match_score` 但按 `Application.id desc` 排序。建议提供按匹配度排序的榜单视图 + 成绩段分布。
4. **AI 评分通道可观测**：`AICallLog` 表已定义但全库零写入点。建议 provider 每次调用落库（业务类型/耗时/状态/降级原因），新增 `GET /ai/channel` 类接口暴露当前通道与降级状态。
5. ~~**假字段治理**~~ ✅ **已完成（2026-09-29，决策：不接云端 ASR，假指标清零 + 浏览器原生能力）**：`speaking_rate/filler_count` 接口入参移除、写入语义改为 0=未测量、模型默认值与种子数据同步修正、历史假数据启动清洗归零；语音作答改为浏览器原生 Web Speech API 转写（含降级提示），"重听题目"改为真实 `speechSynthesis` 朗读，创建页设备检测全部真实化（含后端往返实测）。列保留（SQLite 不支持删列）但不再承载假数据。
6. ~~**next_action 自适应追问失效**~~ ✅ **已完成（2026-09-28）**：整卷预生成后评分建议原本只落库不影响出题；现由 `interview_core._maybe_followup` 驱动——答得好插入同技能更高难度题、答得差插入更低难度题，卷面题号后移、总题数 +1（每场上限 2 次），前端提示追加，卷面快照记录 `followup_count`。
7. ~~**题库无管理界面**~~ ✅ **已完成（2026-09-28）**：管理端 M08 新增 `views/admin/QuestionBank.vue` 与 `/admin/question-bank` CRUD 端点（仅管理员角色）；支持分页筛选、参考答案要点编辑、启用/停用（不物理删除）；新题 `source=MANUAL` 不被种子重建覆盖。
8. ~~**面试历史对比弱 / 缺错题重练**~~ ✅ **已完成（2026-09-28）**：`GET /interviews/history-comparison` 输出同岗位逐维趋势与 delta；`GET /interviews/weak-questions` 按 `bank_id` 聚合最近得分判定薄弱；面试记录页双卡展示并支持"一键重练"——复用 `selected_bank_ids` 按指定考卷开考，`Interview.purpose=RETRAIN` 使其默认不计入成长曲线与对比。

## 五、平台基础能力与工程化（P2）

1. **缓存与限流缺失**：`config.py` 中 `REDIS_URL` 仅在 `.env.example` 注释存在、未在 Settings 声明，无任何限流中间件。建议接入 Redis 缓存 + 接口级速率限制（登录/注册/AI 接口优先）。
2. **AI 同步阻塞**：简历诊断/面试出题/学习路线生成均为**同步阻塞式**调用（`await` 在请求线程内），高并发下易超时。建议引入异步任务队列（Celery / RQ / FastAPI BackgroundTasks）+ 前端轮询/推送。
3. **登录安全**：无验证码、无登录失败锁定、无设备指纹。建议至少加登录与注册的图形验证码与失败次数限流。
4. **文件安全**：`files.py` 仅校验扩展名与 10MB，未校验真实 MIME / 未做内容脱敏；`MAX_UPLOAD_SIZE_MB` 未在 Settings 声明，大小写死。建议：声明配置项、按 content-type 白名单 + 魔数校验、接入病毒扫描。
5. **邮箱/手机验证缺失**：注册与找回密码均无 `email_verified` / `phone_verified` 字段与验证流程。
6. **告警与监控**：无 `/health`、无 metrics/Prometheus 埋点、AI 调用异常仅靠日志。建议补充健康检查与关键业务指标埋点。
7. **测试覆盖不足**：`backend/tests/test_backend.py` 存在但环境未安装 `pytest`，缺少端到端与回归用例。建议补齐 `pytest`/`httpx` 依赖并建立 AI mock 模式下的稳定回归集。

# 功能模块完善与实现建议

> 本文档基于当前代码库（`ai-interview-hub`，Vue 3 + Element Plus 前端 / FastAPI + SQLAlchemy 后端）的现状盘点，列出尚需完善或未实现的功能模块，并给出实现建议与优先级。
> 优先级约定：**P0** = 功能断裂/安全隐患（必须修）；**P1** = 功能补全（影响体验闭环）；**P2** = 平台化与工程化（稳定后推进）。
> 已完成的功能模块已移至 [update_log.md](./update_log.md)（含第 1、2、2.5、3.5 批与题库管理/历史对比等 B 类补全：账号安全、能力诊断与岗位匹配真实化、消息推送与会话落库、模拟面试题库与组卷引擎、面试状态机与自适应追问、题库管理界面、薄弱题重练、学习路线模板库与能力分闭环等）。

## 一、总体结论

- **核心短板集中在**：① 企业/管理端统计指标仍有写死项（招聘数据分析、AI 服务监控）；② 模拟面试仅剩候选人匹配度排行榜、AI 通道可观测（见第四章）。~~③ 平台缺少缓存、限流、异步任务、监控等基础能力~~ → 经 2026-09-29 范围决策，此类企业级能力与演示定位不匹配，已划入第五章 5.2「范围外」，不再是短板项。
- **已完成的补强（2026-09-28~29）**：面试会话状态机与非法迁移拦截（409）、中止面试端点、REST/WS 双通道统一核心服务、next_action 自适应追问真实生效、整场计时服务端化与归零自动交卷、**单题服务端超时校验与报告时间维度分析**、报告/列表/成长中心假数据清理、**语音假字段清零 + 浏览器原生转写/朗读 + 设备检测真实化**；**题库管理界面（M08）**、**同岗位历史对比**与**薄弱题一键重练**（B 类第 6、7、8、9 项全部完成，详见 update_log 与第四章标注）。
- **已完成的补强（2026-09-30，学习路线）**：**模板库混合架构**（5 个 AI 岗位模板含产出物/推荐资源/周期，命中模板走骨架 + 薄弱项个性化、未命中回退 LLM）、**打卡能力分闭环**（UserCompetency +2 + PRACTICE 历史，幂等）、**进度 PATCH 接入**（滑块记录中间进度，100% 视同完成）。详见 update_log 2026-09-30。
- **已完成的补强（2026-09-30，个人中心假数据清理）**：前端 5 页（Settings/GrowthCenter/Dashboard/Assessment/LearningRoadmap）+ 后端 5 接口（dashboard/competencies/evidence/learning plan/profile）的写死兜底全部移除，统一改为"无数据即空态 + 引导"；修复 Settings 授权/会话字段错位 bug（真数据显示成假文案）；打卡接口对不存在任务改 404，前端不再吞错。另修复面试间摄像头镜像（`scaleX(-1)`）。至此求职者端页面展示的数据全部来自后端真实查询。详见 update_log 2026-09-30。

## 三、平台管理端

### 3.1 AI 服务监控（P1）
- `backend/app/api/v1/admin.py` 的 `get_ai_providers` 写死 `success_rate: 99.8` 等指标。
  - 建议：从 `ResumeAIAnalysis` / `AnswerEvaluation` / `OperationLog` 真实统计调用量与成功率；`AI Provider` 增加每次调用的 token 用量与耗时记录，便于成本核算。
  - 进展（2026-09-30）：`get_ai_providers` / `update_ai_providers` 已改为读写真实配置（`system_settings` 表，登录前配置向导同步落地，见 update_log）；**统计指标（成功率/延迟/调用量）仍为写死，待本条建议的落库统计实现**。

### 3.2 AI 引擎页面化配置（P1）✅ 已完成（2026-09-30）
- 背景：本项目定位为源码自部署，原配置只存在于 `.env`（改后需重启），部署者上手门槛高。
- 落地：`system_settings` 键值表 + `services/ai_settings.py`（优先级 DB > .env > 默认，缓存即时失效）；登录前公开接口 `GET/PUT /public/ai-settings` + `POST /public/ai-settings/test`（首次匿名可写、之后仅管理员；Base URL 协议校验；Key 掩码回显）；前端 `/ai-setup` 向导页（服务商预设、测试连接）与登录页引导横幅；`AIProvider` 动态读取，13 处调用点零改动。

## 五、平台基础能力与工程化（P2）

> **2026-09-29 范围决策**：本项目定位为**竞赛作品 / 校内演示**（SQLite 单文件、预置演示账号、单机启动），
> 不存在公网匿名攻击者与企业级并发。原则：**砍掉所有"防御不存在威胁"的功能，保留所有"让演示数据说真话"的功能。**
> 以下条目已按此决策分为"保留待做"与"范围外（明确不做）"两组。

### 5.1 保留待做（低成本高价值）

1. **文件安全（部分保留）**：`files.py` 已校验扩展名与 10MB；补充 `MAX_UPLOAD_SIZE_MB` 配置化与 MIME 魔数校验（半天工作量）。~~病毒扫描~~ 划入范围外。
2. **健康检查**：补一个 `GET /health`（返回 DB 连通与题库就绪状态），评审/部署探活有用。Prometheus 埋点划入范围外。
3. **测试覆盖**：`backend/tests/test_backend.py` 存在但环境未装 `pytest`；现有三套冒烟脚本（44+26+33 断言）改造为 pytest 用例集，报告可写"自动化回归测试"。
4. **基础安全收尾**：`SECRET_KEY` 改为部署时随机生成、CORS 收紧到实际前端域名（合计约 10 分钟）。

### 5.2 范围外（演示定位，明确不做，非遗漏）

| 项目 | 砍掉理由 | 现状兜底 |
|---|---|---|
| 登录验证码 / 失败锁定 / 设备指纹 | 防撞库脚本，演示账号全部公开 `123456`，威胁不存在 | — |
| 接口限流（Redis/slowapi） | 并发上限为一个教室的学生；内存限流器多进程失效，做了是假安全 | LLM 调用失败已有 mock 回退 |
| Redis 缓存 | 86 题 + 几十用户，SQLite 查询 <1ms | — |
| AI 异步任务队列（Celery/RQ） | 需 broker+worker+任务表+前端轮询四件套；单机演示同步等待 20s 可接受（前端已有 loading） | 超时自动回退 mock 评分 |
| 病毒扫描（ClamAV） | 独立守护进程 ~1GB 内存，部署成本远超收益；上传者即演示者本人 | 扩展名 + 10MB 校验 |
| 邮箱验证 / 手机验证 | 手机短信需企业营业执照与签名审核（个人拿不到资质）；邮箱验证需真实 SMTP | 找回密码走 `dev_reset_token` 开发令牌流程；`.env` 配置 SMTP 后自动切换真实邮件 |
| Prometheus metrics / 告警 | 单人维护项目没有值班对象 | 日志 + `/health` |
